# Ordinary ChatGPT Images — experimental browser route

Project decision, 2026-10-13: the user has put this route aside after the slow pilot and chosen built-in Codex/imagegen for subsequent generations. Preserve the browser archive; use this route again only if the user explicitly chooses it anew. No cost or speed advantage has been established.

Use only when the user selects this route and an authorized browser can access their ordinary ChatGPT account. Keep Chat selected; Work is a different route. The agent still runs the cutaway skill locally: store photo, manufacturer evidence, fixed reviews, v1.2 budget (five images plus two technical retries), chosen-base90 caption gate and final selection are unchanged. This is a tool-guided browser workflow, not a standalone browser daemon or proof of cheaper usage.

- Bind the observed tab through the available computer-use API. Let the user complete sign-in when needed. Read the current conversation/draft before any send; preserve unrelated user drafts and chats.
- Use currently declared WebMCP tools when available; discover them anew per turn/navigation. The signed-out page advertised tools that were absent after sign-in in the pilot. Otherwise use the observed ordinary UI/file chooser. Do not guess hidden request endpoints or copy cookies between browsers.
- Reserve each request and mark dispatch immediately before sending, including edits and failed sends. Save the actual dispatched prompt (the Create image action can append a marker), file roles/hashes and conversation URL. For a linked revision, retain its external parent seed and the original store-photo provenance. The existing helpers use generate for a first external seed and edit with an in-run parent afterwards; record actual image-edit intent separately.
- Send the saved public reference files through the normal uploader, verify uploads are finished, select Create image and send once. A dispatch, local temporary conversation URL, progress percentage or Preview is not a completed result. Wait for the corresponding response to settle and identify its actual generated image; a stale Response complete notice from an earlier turn is insufficient while Stop/current generation is still active.
- Download the corresponding image through the observed image/download control, inspect actual file format and save it with record before review. Do not replace a generator output with a page screenshot. Preserve any additional returned variants separately without inventing extra dispatches or ratings.
- Review the whole frame and nodes, compose/inspect captions locally at chosen technical90+, show the draft immediately, and continue source-supported edits within the saved budget. Request90+ is a target, not a substitute for observations or expert approval.
- On an error, capture a sanitized screenshot and check saved history/result before resending. A normal reload recovered account loading and revealed unsaved failed sends in the pilot. If a new request is warranted after confirmed failure, reserve a new attempt. Never press Retry blindly or count it as free. A fresh ordinary chat with the chosen PNG and necessary cached evidence succeeded after a failed same-chat send; consider this recovery when appropriate, keep the previous chat and log the local linkage. It is an observed option, not a rule that every edit must open a new chat. If a security check requires user action, hand off that check; do not bypass it.
- Save browser failures and successful/uncertain steps alongside the run. Keep credentials, unrelated chats and personal home-page suggestions out of Git. Tool availability, access stability, multiple-product concurrency and resource savings require their own validation; a single successful edit does not establish them.

Do not silently fall back to Codex/imagegen on a browser failure when the user selected ChatGPT Images. Follow the normal stop/continuation protocol; confirmed failures use the saved bounded retry allowance; uncertain responses must be resolved before re-sending. Report the chosen image, raw/captioned rating, remaining gaps and unresolved browser failures separately.
