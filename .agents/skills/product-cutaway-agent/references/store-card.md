# Store card intake

For each new product, use the actual 477477.ru card as the origin of its name and exterior photograph. User input can be a card URL, article, name or list of products. Each product has its own input record and run; do not mix similar variants' titles, photos or documentation.

1. Find and open the exact card. Use article, brand/model, variant and relevant specification to distinguish similar products. A search-result snippet is a discovery aid, not the copied card content. Ask only if a consequential ambiguity cannot be resolved.
2. Copy the complete visible product heading verbatim, including model suffixes, dimensions/units and descriptive additions. Do not copy a truncated search title, SEO page title or add words from memory. Keep the canonical manufacturer model and article separately for matching documentation; they do not replace the verbatim store title.
3. Inspect the card's product gallery. Save the real main photograph from an image URL actually observed in that card/gallery, preferably its original/largest available version. Inspect the saved image to verify it is the exact item, not packaging, an accessory or a related product. A CDN URL is acceptable if its association with the card was observed; do not guess asset URLs. Preserve original bytes and actual PNG/JPEG/WebP format. Do not screenshot the entire card, recreate the object or substitute another site's image for the product photograph.
4. Record provenance alongside the input: card_url, title_verbatim, article, manufacturer_model, image_url, retrieved_at, local_image and image_sha256. Save the needed card excerpt or explicit archival gap. Register the product photograph as kind product_photo, with the actual asset URL and card association in sources.json; it proves the exterior, not the internals. Use the init result's input_image path rather than assuming reference.png.
5. Show the full title, clickable card link and the saved local photograph inline in chat. Use an absolute local path in the Markdown image tag. Then continue autonomously with manufacturer research, frozen protocol v2 checks and up to5 generation calls. This message is not a new confirmation request; clarification is needed only for unresolved identification or access.

If one retrieval route fails, try the available authorized browser/card access before declaring intake blocked; a single HTTP403 does not establish that all routes are unavailable. If the card or its image still cannot be read/saved using available authorized tools, record the concrete failure and tell the user that intake is incomplete. Do not spend generation attempts and do not silently use a user attachment, manufacturer image or search thumbnail instead. A substitute requires a specific user instruction for that item and must retain its true provenance. Earlier AQUARIO pilots used user-supplied photos under earlier instructions; those historical records are unchanged and must not be relabelled as store downloads.

For a linked image-edit revision, preserve the inherited base and its recorded store-photo origin; no need to reacquire the same card for a caption-only edit. Recheck the card if product identity/variant changes.
