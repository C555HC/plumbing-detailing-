# Product cutaway agent

Produce a recognizable product cutaway showing its main functional nodes and how they connect. Use a white background and Russian labels unless the user specifies otherwise. Deliver the best PNG, all variants, and a source-backed report. Execute in an active Codex task; this skill is not a background service.

Generate a DRY device only: no water/liquid, blue-filled passages, droplets, bubbles, or flow arrows baked into the base image. Label leaders are allowed in the separate caption composition. A requested flow explanation is a separate editable overlay/output, after physical passages are verified; preserve the dry master. Read [layers.md](references/layers.md).

Cut faces retain the part's material: metal at a metal section, polymer at a polymer section, elastomer at a membrane. No red/colored contour bands, painted cut faces, neon rims or decorative surface patterns unless specifically requested. Preserve readable edges through lighting and real wall thickness.

## Start or resume

- For a new product, find the exact card on 477477.ru from the user's URL/article/name. Open the card, copy its full visible product title verbatim and save the actual product photograph served by that card. Follow [store-card.md](references/store-card.md). Show the title, card link and saved photo inline in chat before manufacturer research and generation; this is a source checkpoint, not an approval pause. Do not automatically substitute an attachment, manufacturer photo, search thumbnail or a recreated product image when the card is inaccessible. Historical edit runs keep their recorded origins.
- Identify the manufacturer model/article from that card and photo without replacing the copied store title. Ask only when a consequential ambiguity blocks identification. Read [evidence.md](references/evidence.md) to gather applicable manufacturer sources and reconstruction gaps. Consult the matching entry in [manufacturer-sources.md](references/manufacturer-sources.md) and check the manufacturer's service/parts/3D viewer before analogs. Record which source types were inspected or unavailable. Do not assume brand-wide coverage or internal detail in a BIM model.
- Use the built-in image generation/editing tool; inspect local reference images before passing them. Do not switch to an external paid API without authorization. Python helpers save state and calculate scores; they do not invoke this tool.
- Use `scripts/cutaway.py` through a Python with Pillow. For commands and JSON formats, read [execution.md](references/execution.md). New runs require scoring protocol v2: separate applicable aspects of essential nodes, explicit source support, and readiness distinct from rating; read [review.md](references/review.md). Freeze spec, sources, and checklist before the first call. For resume, read existing state and current inputs rather than reconstructing from chat. Historical runs keep their original budgets/checklists until explicitly revised.
- Archive inspected source pages/views with `archive-evidence` after preparing inputs; record an explicit gap when no local asset can be saved. Read [evidence.md](references/evidence.md). Do not confuse a URL with a preserved view or claim that legacy uncached views were recovered.

## Iteration

1. Create one initial variant from the source photo and technical constraints. Use [prompts.md](references/prompts.md). Before EVERY generation/editor call reserve one attempt with its actual prompt and references. New runs have a maximum of 5 calls (default 5), including failed calls; do not exhaust the budget just to raise a number. Never reset a counter to continue a stalled run.
2. Save the returned PNG immediately with `record`. A lost/uncertain response uses `fail --unknown`; seek an existing result before issuing another distinct call. Keep all outputs. Copy tool output into the run; never leave the only copy in the tool's default folder.
3. Inspect the new complete image and each functional node at readable scale against the frozen checks. Read [review.md](references/review.md). Compare an approved reference by node when supplied, recording its provenance and technical approval status. Save concrete observations, not a guessed overall score; `review` computes the score. Missing/hidden details are unknown. Reconstruction from analogs never proves this model's geometry.
4. Start with the unlabelled base. Review caption-dependent checks as unknown/zero; new runs require a base score of80 or above before captioning. At the first qualifying result, compose title/labels/leaders with compose_png.py, inspect every name and endpoint against its source, register with review --preview --labels --label-review, and immediately show the captioned PNG in chat as a reviewable draft, with base rating and remaining issues. Do not wait until the end of five calls or ask for another confirmation. For subsequent qualifying variants, recheck targets and update captions without image generation. See [execution.md](references/execution.md). The final PNG is flattened; editable base/labels remain separate. The helper validates metadata and hashes, not the truth of visual observations.
5. Write the next corrective prompt from actual defects and sources; preserve correct parts. Edit the current candidate or a previous leader. A new candidate is allowed when the cut plane fails. Re-check the whole new image after edits. Ratings can decrease.
6. After the second successful output, check whether further generation has a concrete, substantial, source-supported purpose. If only minor visual flaws remain, stop and list manual finishing options; captions use composition without generation. Stop at the limit or earlier when no substantial defensible correction remains. Re-review the top two when available without past ratings. Use `finalize` to select the best candidate without critical contradictions first, then by score. Report readiness separately: critical errors, essential reconstruction/unverified facts, or prepared for technical review. No automatic status constitutes expert approval.

## Brief communication and revisions

During generation say: `Генерируется 3/5. Картинка 2: 70/100. Исправляю: …` using actual numbers and the saved run's actual limit. Keep detailed observations and prompts in files. Cache sources/spec and load relevant pages rather than entire PDFs or all prior images each time. Whole-image regression inspection remains necessary.

Distinguish the unlabelled base score from the captioned deliverable score; caption points are not construction improvements. At80+, show the captioned draft immediately so the user can check node names/positions and steer ongoing work. At completion choose one main image and keep all alternatives. If no base reaches80, disclose that and return the best unlabelled available result rather than inflating ratings or secretly spending additional calls. Historical completed pilots and caption-only edits retain their original records/mode.

At completion show the best PNG inline, its rating and readiness, a brief source-confirmation summary, a compact table of other versions, and links to all variants/report. Disclose analogs and missing evidence in the adjacent report, not on the image. A score is a comparative rating, never a probability of correctness. Human technical approval is a separate status.

For follow-up edits preserve the chosen version and read [revisions.md](references/revisions.md). During explicitly authorized skill development, fix code/process failures, run relevant regression tests, and log unresolved failures; a routine product run does not authorize rewriting the installed skill. Never publish to a store as part of this skill.
