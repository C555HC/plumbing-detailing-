## Переиспользуемые инструменты

- `prepare --bundle`: данные одной структуры вместо одноразового Python-builder на каждый товар.
- `continue`: новый явный связанный раундv1.2, оригинальное фото/источники, выбранная база как seed, старая история сохраняется. Сам ничего не генерирует. Legacy-запуск требует явной подготовки origin/плана; автоматической миграции нет.
- `source_cache.py`: кеш локальных исходных видов поURL/модели/редакции/локатору, контроль байтов/блокировка записи. Live-актуальность и применимость агент проверяет отдельно.
- `review-packet`: отдельный кандидат и факты/источники без весов, оценок, номера попытки, промпта и истории. Сохраняется привязка к хешам. Это подготовка контекста, не запущенный независимый оценщик.

## Ход проверки и обнаруженные проблемы разработки

Сначала сохранён полный набор79 регрессийv1.0 с явным legacy-режимом. Затем добавлены отдельные тестыv1.2. Первый общий прогон показывал128 тестов: импорт тестового класса ошибочно запустил исторические сценарии второй раз. Исправлен импорт — повторный запуск больше не выдаётся за дополнительное покрытие. Добавлены проверки новых CLI-путей/продолжения/кеша и причин переоценки. Итоговый прогон:111 тестов (79 прежних +32 новых), все прошли. Выполнен полный CLI-маршрут на синтетическом запуске: prepare→archive→reserve→dispatch→record→review→finalize, а не только отдельные функции. Валидатор skill-creator: Skill is valid; git diff --check без ошибок. Новая проверка чистого отказа при попытке подписать ещё не оценённую базу выявила/закрыла потенциальный IndexError: теперь возвращается понятный ValueError.

Исходные синтетические PNG и фиктивные источники специально используются для контрактов кода. Эти тесты **не проверяют инженерную правильность пикселей**. Новые генерации и дополнительные модельные проверки в этом этапе не запускались, картинки товаров не удалялись. Полноценная экспертная/слепая проверка потребует реальных изображений с размеченными ошибками.

## Нерешённые ограничения

1. **R02 остаётся частично открытым:** помощник складывает наблюдения агента и не умеет сам распознавать неверный механизм. Даже после разделения шкал ложный pass может дать100. Пакет проверки уменьшает подсказки для будущего оценщика, но его модель ещё не согласована/не запускалась.
2. Нормировка85 сохраняет прежние внутренние веса45/25/15. Веса/порог90 не откалиброваны техническим специалистом; старые и новые числа нельзя сравнивать напрямую.
3. Малая модель может пропускать сложные ошибки. Предложен ограниченный тест Luna на одном финальном кандидате; расход пятчасового окна и качество не измерены. Числовую экономию не обещаем.
4. Происхождение/локаторы/факты/assessor — зарегистрированные утверждения проверяющего. Хеши защищают от случайного рассогласования, не от одновременной подмены state и контрольных сумм. Они не доказывают веб-происхождение и честный осмотр.
5. Команды не перехватывают вызовы imagegen вне протокола. Dispatch — локальная отметка границы отправки, а не серверная квитанция. Между ней и реальным вызовом возможен сбой: его нужно честно разрешать как uncertain.
6. Файловая фиксация state атомарна, но набор файлов не единая транзакция. Авария может оставить orphan-файл/новую папку продолжения; требуется осмотр, никакого автоматического удаления доказательств.
7. `fcntl` требует macOS/Linux. Полный импортCAD/видео и автоматическая проверка всех пересечений/семантики выносок не реализованы.
8. Очистка — только идея с обязательным отдельным подтверждением. Никаких команд удаления промежуточных данных не добавлено.
